## Google Play — Data safety form

No server, no account. All gameplay data stays on the device in local storage. Data collection comes only from the AdMob SDK (ads) and the RevenueCat SDK (purchase).

| Question | Answer |
|---|---|
| Does your app collect or share any of the required user data types? | **Yes** |
| Is all of the user data collected by your app encrypted in transit? | **Yes** |
| Do you provide a way for users to request that their data be deleted? | **No** (nothing is stored on our servers; uninstalling clears local data). If Play requires a URL, point to the privacy page section on data. |

Data types:

| Data type | Collected | Shared | Optional? | Purposes |
|---|---|---|---|---|
| Device or other IDs (advertising ID) | Yes (AdMob) | Yes (AdMob) | Required | Advertising or marketing, Analytics, Fraud prevention |
| App interactions (ad views / clicks) | Yes (AdMob) | Yes (AdMob) | Required | Advertising or marketing, Analytics |
| Crash logs / Diagnostics | Yes (AdMob SDK) | No | Required | Analytics |
| Purchase history | Yes (RevenueCat, only if the user buys Remove Ads) | No | Optional | App functionality |
| Approximate location (IP-derived, by AdMob) | Yes | Yes | Required | Advertising or marketing |

Also: target audience is **13+** (not designed for children), so the Families policy does not apply. The app contains ads: **Yes**.

## App Store — App Privacy ("nutrition label")

| Data type | Linked to user? | Used for tracking? | Purposes |
|---|---|---|---|
| Identifiers → Device ID | No | **Yes** (only if the user allows ATT) | Third-Party Advertising |
| Usage Data → Advertising Data | No | **Yes** | Third-Party Advertising, Analytics |
| Usage Data → Product Interaction | No | No | Analytics |
| Diagnostics → Crash Data, Performance Data | No | No | App Functionality, Analytics |
| Location → Coarse Location | No | **Yes** | Third-Party Advertising |
| Purchases → Purchase History | No | No | App Functionality |

- The **ATT prompt** is requested natively in `ios/App/App/SceneDelegate.swift` once the app is active. The prompt text lives in `Info.plist` as `NSUserTrackingUsageDescription`.
- `PrivacyInfo.xcprivacy` comes from the AdMob and RevenueCat SDKs through Swift Package Manager. In Xcode, check **Product → Archive → Generate Privacy Report** before submitting.
- **Export compliance:** the app uses no non-exempt encryption (HTTPS only). Answer "None of the algorithms mentioned above". To skip the question on every upload, `ITSAppUsesNonExemptEncryption = NO` can be added to Info.plist.

## Release steps (Brian)

Follow **`MONETIZATION_INSTRUCTIONS.md` → Final release checklist** first: real AdMob ids, RevenueCat keys, IAP products, privacy page live. Then:

1. `npm run build && npx cap sync`
2. **Android:** in Android Studio, Build → Generate Signed App Bundle, using the upload key you keep for BigSimple apps. Upload the `.aab` to Play Console → Internal testing. Fill in the store listing and the data safety form from this file, then promote to Production.
3. **iOS (on the Mac):** open `ios/App/App.xcodeproj`. Packages resolve through SPM, so there's no `pod install`. Set the Team under Signing & Capabilities. Product → Archive → Distribute to App Store Connect. Fill in the listing and App Privacy from this file, attach the `threadily_remove_ads` IAP to version 1.0, and submit.
4. Bump versions for later releases with `bump-version-android.sh` / `bump-version-ios.sh`.
